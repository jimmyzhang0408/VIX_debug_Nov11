# Vanta iX 现场监控 · 0.2.0-field.1

## 开始监控

1. 在 Windows x64 电脑上解压或复制整个 `VantaListener` 目录。选择可写目录。保留 EXE 旁边的 `_internal`。
2. 双击 `VantaListener.exe`。确认窗口标题显示 `0.2.0-field.1`。
3. 选择“设备监听”。填入现场的设备 IP 和端口。只监听设备 API 时，将 Arduino 串口留空。有配套板时才输入实际 COM 口。
4. 点击“开始监听”，确认 API 已连接。记录 PLC 项目、设备编号、工位、批次号和开始时间。先做一轮正常检测，确认“触发对账”记录及最终结果文件。
5. 批次开始前使用“Reset 计数”。在批次内保留 PLC 工件号、START 与结果确认。批次结束后保存 EXE 旁的 `runtime/logs`、`runtime/results`、`runtime/summaries` 和同段 PLC 记录。

## 现场判定

- **未见设备响应**需要独立板端触发。只用 WebSocket 时，程序可从设备的 `702/704` 查找“设备已见触发 · 未见启动”。要定位未发出或未到达设备的 START，请核对 PLC。
- **正常停测 · 未收终态**表示正常 `201` 后，在 5 秒窗口内没有配对的最终 `206`。用设备数据库和发送端记录核实。
- **异常停测**包括接近故障和中止。程序保留该轮收到的结果。正常停测同时收到错误结果时，例如 `statusId=-2998`，显示“终态结果报错”。
- **无法判定**需要检查原始报文、断线和写盘记录。试验记录中保留这些周期。

最终 `206` 可在 `201` 前或后到达。界面和汇总以结果有无、配对和停测状态为准。跳号在对账页单独显示。

在受控台架验证正常检测、接近故障、重复触发和断网。生产线上使用批准的测试程序。首次运行后确认设备实际提供哪些触发通知，并复核 3 秒响应、5 秒启动及 5 秒终态窗口。

## 版本复核

对 `3d795e6` 增加的编号配对规则进行了复核。测试复现了相邻周期误配，接近故障的迟到终态被分给下一轮，下一轮因此被误判为正常。现场版按已有的 `testID` 和设备检测时间配对。碰到证据不足的情况标为“无法判定”。跳号供核查，缺终态依照等待窗口结案。
